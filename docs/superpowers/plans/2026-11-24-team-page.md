# Team page, leaner leaderboard and no freeze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the score freeze, serve one cached `/leaderboard` payload holding ranked teams and the ladder, add Hide/Show leaderboard buttons to the scoreboard header, and add a per-team `/team` Razor Page backed by `GET /progress`.

**Architecture:** All ranking, ladder grouping, unlock state and percentages are computed in .NET. `LeaderboardCache` serializes one compact JSON snapshot per change, which both `GET /leaderboard` (with ETag/304) and the SSE `leaderboard` event write unchanged. The `/team` page is server-rendered from `PuzzleCatalogue` and `ShowEndpoints`; a small `team.js` only fetches `/progress` with the team headers and puts values into the DOM.

**Tech Stack:** ASP.NET Core (net10) minimal APIs + Razor Pages, NUnit, plain JS/CSS in `wwwroot`.

**Spec:** `docs/superpowers/specs/2026-11-24-team-page-design.md`

All paths below are relative to `ChristmasKataServer/` (this repo's root). Code lives in `ChristmasKataServer/WebAPI/`, tests in `ChristmasKataServer/Tests/`.

## Global Constraints

- JS never computes ranks, unlock state, percentages or ladder grouping. It only writes server values into the DOM.
- `/leaderboard` JSON is compact (no newlines) camelCase UTF-8, serialized once per change; GET and SSE write the same bytes.
- Rank: tied totals share a rank and the next rank skips (1, 1, 3). Order: total descending, then team name ordinal.
- `/progress` answers only for the team whose `X-Team-Name`/`X-Unique-Key` it gets; unknown team or key gets `401`.
- `/progress` statuses are exactly `passed`, `current`, `locked`; `next` is the first `current` id or `"santa"`.
- `showsUnlocked` is `Participant.MayShow` (full marks on 7.1), from live `BestCorrect`.
- Light-show copy numbers come from `ShowEndpoints.FrameRows` (48) and `ShowEndpoints.MaxFrames` (500), never literals in the page.
- Locked light-shows heading: "Unlocks with full marks on 7.1". Unlocked heading: "Light shows unlocked: your pattern goes on the big screen".
- Error copy on `401` in the team page: "Team name or key not recognised".
- Scoreboard buttons: "Hide leaderboard" / "Show leaderboard"; only one visible; state in `localStorage`; header's existing type size and colours.
- No scoreboard restyle beyond the header buttons and the hidden-standings grid state.
- Old stored documents with a `PublicBestCorrect` field must still load.
- Run tests: stop the dev server first (`taskkill //F //IM WebAPI.exe`), then `dotnet test` from `ChristmasKataServer/`.
- Commits stay local. Never push.

## Review Focus

- A team with no submissions at all: `/progress` returns 1.1 `current`, everything else `locked`, every `percent` null, `next` "1.1". Test in Task 4.
- A team that passed 1.1 with 80% but not 100%: 1.1 `passed`, 1.2 `current`. Test in Task 4 (pass threshold, not full marks).
- Empty leaderboard (no teams): `/leaderboard` returns `{"teams":[],"ladder":[...]}` with a valid ETag, not an error. Test in Task 2.
- `If-None-Match` stale after a new score: the ETag changes and the GET answers `200` with the new body. Test in Task 2.
- Team names containing HTML (`<b>x</b>`): team page and scoreboard insert names with `textContent`, never `innerHTML`. Checked by review in Tasks 3 and 5; Razor encodes server-side by default.
